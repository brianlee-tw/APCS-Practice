Algorithm / Complexity

TLE 怎麼判斷：先看 Big-O

先判斷方法的數量級，再做優化。很多 TLE 並不是 I/O 太慢，而是核心工作重複了太多次。

閱讀時間4–5 分鐘
能力Algorithm
核心概念Complexity

第一個問題：會做多少次核心操作？

O(n²) example
for (int i = 0; i < n; ++i)
  for (int j = 0; j < n; ++j)
    work();

這個結構是 O(n²)。當 n 很大時，單純把輸入換快一點通常無法改變結果，因為真正的問題是操作次數本身。

先看 constraints，再猜方法

如果輸入規模從幾千變成幾十萬，原本可以接受的雙層迴圈往往就不再合理。

快速檢查流程

  • 讀 constraints，先知道資料規模。
  • 估算目前方法的 Big-O。
  • 找出最深層、最重複的工作。
  • 考慮排序、二分、前綴和、資料結構等方式減少重複計算。
  • 最後才做 I/O 或常數級優化。
